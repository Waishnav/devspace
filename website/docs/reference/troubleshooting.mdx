---
title: Troubleshooting
description: The setup issues people hit most, and the one-line fix for each.
---

Start with `devspace doctor` — it reports config, Node, Git,
Bash, public URL, allowed hosts, and SQLite status.

<Accordion title="devspace: command not found">
  Open a new terminal so the installer's `PATH` change applies, or rerun the
  installer. With an npm install, make sure npm's global bin directory is on
  your `PATH`.
</Accordion>

<Accordion title="Unsupported Node version">
  DevSpace requires Node `>=22.19 <27`. Install Node 22 LTS with `nvm`, `fnm`,
  or `mise`.
</Accordion>

<Accordion title="better-sqlite3 could not load (DevSpace 1.0.x)">
  DevSpace 1.1 uses Node's built-in SQLite, so this only affects 1.0.x
  installs, whose native SQLite module was built for a different Node runtime.
  The simplest fix is to upgrade with the installer above. To stay on 1.0.x,
  reinstall with the Node you run DevSpace with, then rerun `doctor`:

  - global install: `npm install -g @waishnav/devspace@1.0.8`
  - npx: remove only DevSpace's cached copy, then rerun the `npx` command.
    With npm 11.2 or newer, find its key in `npm cache npx ls` and run
    `npm cache npx rm <key>`. With older npm, switch to a global install.
  - local project install: `npm rebuild better-sqlite3` in that project
</Accordion>

<Accordion title="Public URL includes /mcp">
  Setup wants the origin (`https://host`); the client wants the endpoint
  (`https://host/mcp`). Fix it with
  `devspace config set publicBaseUrl https://host`, then restart `serve`.
</Accordion>

<Accordion title="Tailscale Funnel /mcp returns 404">
  Run `tailscale funnel --bg 7676` from the root. Do not use
  `--set-path=/mcp` — Funnel strips the mount path, and DevSpace also needs its
  OAuth routes.
</Accordion>

<Accordion title="403 Invalid Host">
  Allowed hosts derive from `publicBaseUrl`, so every request through a
  different hostname is rejected — including OAuth discovery, which hosts
  report as a sign-in or registration failure. If you switched tunnels, run
  `devspace config set publicBaseUrl https://new-host` and restart `serve`.
</Accordion>

<Accordion title="Claude: &quot;Couldn't register with DevSpace's sign-in service&quot;">
  Claude registers an OAuth client with a `claude.ai` callback. Check that
  `curl https://your-host/healthz` works through the tunnel (see Invalid Host
  above), and that `oauth.allowedRedirectHosts` includes `claude.ai` — an
  explicit list in your config replaces the default, which includes it.
</Accordion>

<Accordion title="OAuth redirect host rejected">
  Registration fails with `Client redirect_uri is not allowed`. Add the
  client's redirect host to `oauth.allowedRedirectHosts` and restart `serve`.
</Accordion>

<Accordion title="Unknown workspace_id">
  Workspace session metadata is persisted, so IDs survive server restarts.
  Keep using the existing ID; call `open_workspace` again only when a tool
  rejects it as unknown. Optional OpenAI conversation metadata can recover the
  same checkout workspace on a repeated open; other hosts receive a new one.
  Every worktree open creates a new workspace with full context. See
  [Workspaces](/concepts/workspaces).
</Accordion>

<Accordion title="Workspace path rejected">
  `open_workspace` paths must be inside an allowed root. Check with
  `devspace config get` or rerun `devspace init --force`. Restart `serve`
  after changing allowed roots; configuration does not hot-reload.
</Accordion>

<Accordion title="Worktree mode fails">
  It needs Git, a repository with at least one commit, and a `base_ref` that
  resolves. Uncommitted changes are not copied into the worktree.
</Accordion>

<Accordion title="Shell commands fail on Windows">
  DevSpace's Bash tools need Bash. Install Git for Windows (Git Bash), or use
  WSL, MSYS2, or Cygwin Bash. Native PowerShell and `cmd.exe` execution are not
  supported by the Bash tools. Run `devspace doctor` to confirm Bash is detected.
</Accordion>

<Accordion title="PROVIDER_UNAVAILABLE">
  The provider's CLI isn't installed or isn't on `PATH` for the user running
  DevSpace. Install it, or point DevSpace at it with the provider's `command`
  setting or its `*_COMMAND` variable (`CODEX_COMMAND`, `CLAUDE_COMMAND`,
  `OPENCODE_COMMAND`, `PI_COMMAND`, …).
</Accordion>

<Accordion title="A read-only subagent refuses to start">
  `--write-mode read_only` is enforced by the provider itself — Cursor's ask
  mode, Copilot's plan mode. An older CLI that can't switch modes fails the
  turn instead of running with write access. Update the CLI. Generic ACP
  instances support only explicit `full_access`; `read_only` and the default
  `allowed` both fail. See [Providers](/orchestration/providers#any-acp-agent).
</Accordion>

<Accordion title="A subagent provider is missing from targets">
  Confirm it is enabled under `subagents.providers`, that its CLI is installed
  and logged in, and check `devspace agents daemon logs`. A daemon with active
  work returns `DAEMON_CONFIG_CHANGED` until that work finishes, then picks up
  the new configuration.
</Accordion>

<Accordion title="Owner password not accepted">
  Use the Owner password stored in `~/.devspace/auth.json`, or the
  `DEVSPACE_OAUTH_OWNER_TOKEN` override if one is set in the server environment.
  `devspace init --force` preserves the stored owner token; it does not reset
  the password.
</Accordion>

<Accordion title="Skills do not appear">
  Confirm `skills.enabled` is `true`. DevSpace checks `~/.agents/skills`, project
  `.agents/skills`, `~/.devspace/skills`, `skills.agentDir/skills` (default
  `~/.codex/skills`), and `skills.paths`. Relative custom paths resolve from the
  active workspace; add legacy paths such as `.pi/skills` there. Restart `serve`
  after changing configuration. See [Skills](/concepts/workspaces#skills).
</Accordion>

<Accordion title="Review or workspace cards do not appear in ChatGPT">
  Cards are attached only to `open_workspace` and `show_changes`; reads, edits,
  and commands return normal tool results. Check that `ui.enabled` is not
  `false`, restart `serve` after config changes, and reconnect the MCP server.
  Plain MCP clients may show text only; `show_changes` still works.

  If the host restores only structured content, a review card uses its
  `review_ref` to reopen the exact Git-backed review without advancing the
  review point. The workspace card can be rebuilt from its structured result.
</Accordion>

<Accordion title="Local state keeps growing">
  Workspace session metadata, conversation bindings, and review refs have no
  automatic retention pruning. This is separate from `activity.maxTurns`, which
  caps closed activity turns per workspace, and managed worktree cleanup, which
  removes stale worktree directories. Disabling activity stops new recording
  without deleting existing history.
</Accordion>
