---
title: Troubleshooting
description: The setup issues people hit most, and the one-line fix for each.
---

Start with `npx @waishnav/devspace doctor` — it reports config, Node, Git,
Bash, public URL, allowed hosts, and native SQLite status.

<Accordion title="devspace: command not found">
  Use `npx @waishnav/devspace …`, or make sure npm's global bin directory is on
  your `PATH`.
</Accordion>

<Accordion title="Unsupported Node version">
  DevSpace requires Node `>=22.19 <27`. Install Node 22 LTS with `nvm`, `fnm`,
  or `mise`.
</Accordion>

<Accordion title="better-sqlite3 could not load">
  Native dependencies were built for a different Node runtime. Reinstall with
  the Node you run DevSpace with, then rerun `doctor`:

  - global install: `npm install -g @waishnav/devspace`
  - npx: remove only DevSpace's cached copy, then rerun the `npx` command.
    With npm 11.2 or newer, find its key in `npm cache npx ls` and run
    `npm cache npx rm <key>`. With older npm, switch to a global install.
  - local project install: `npm rebuild better-sqlite3` in that project
</Accordion>

<Accordion title="Public URL includes /mcp">
  Setup wants the origin (`https://host`); the client wants the endpoint
  (`https://host/mcp`). Fix it with
  `devspace config set publicBaseUrl https://host`.
</Accordion>

<Accordion title="Tailscale Funnel /mcp returns 404">
  Run `tailscale funnel --bg 7676` from the root. Do not use
  `--set-path=/mcp` — Funnel strips the mount path, and DevSpace also needs its
  OAuth routes.
</Accordion>

<Accordion title="403 Invalid Host">
  Allowed hosts derive from `publicBaseUrl`, so every request through a
  different hostname is rejected — including OAuth discovery, which hosts
  report as a sign-in or registration failure. If you switched tunnels, run
  `devspace config set publicBaseUrl https://new-host` and restart `serve`.
</Accordion>

<Accordion title="Claude: &quot;Couldn't register with DevSpace's sign-in service&quot;">
  Claude registers an OAuth client with a `claude.ai` callback. Check that
  `curl https://your-host/healthz` works through the tunnel (see Invalid Host
  above), and that `oauth.allowedRedirectHosts` includes `claude.ai` — an
  explicit list in your config replaces the default, which includes it.
</Accordion>

<Accordion title="OAuth redirect host rejected">
  Registration fails with `Client redirect_uri is not allowed`. Add the
  client's redirect host to `oauth.allowedRedirectHosts` and restart `serve`.
</Accordion>

<Accordion title="Unknown workspace_id">
  Workspace IDs are session handles. After a server restart, call
  `open_workspace` again.
</Accordion>

<Accordion title="Workspace path rejected">
  `open_workspace` paths must be inside an allowed root. Check with
  `devspace config get` or rerun `devspace init --force`.
</Accordion>

<Accordion title="Worktree mode fails">
  It needs Git, a repository with at least one commit, and a `base_ref` that
  resolves. Uncommitted changes are not copied into the worktree.
</Accordion>

<Accordion title="Shell commands fail on Windows">
  DevSpace needs Bash. Install Git for Windows (Git Bash) or use WSL.
</Accordion>

<Accordion title="PROVIDER_UNAVAILABLE">
  The provider's CLI isn't installed or isn't on `PATH` for the user running
  DevSpace. Install it, or point DevSpace at it with the provider's `command`
  setting or its `*_COMMAND` variable (`CODEX_COMMAND`, `CLAUDE_COMMAND`,
  `OPENCODE_COMMAND`, `PI_COMMAND`, …).
</Accordion>

<Accordion title="A read-only subagent refuses to start">
  `--write-mode read_only` is enforced by the provider itself — Cursor's ask
  mode, Copilot's plan mode. An older CLI that can't switch modes fails the
  turn instead of running with write access. Update the CLI or use `allowed`.
</Accordion>

<Accordion title="A subagent provider is missing from targets">
  Confirm it is enabled under `subagents.providers`, that its CLI is installed
  and logged in, and check `devspace agents daemon logs`. A daemon with active
  work returns `DAEMON_CONFIG_CHANGED` until that work finishes, then picks up
  the new configuration.
</Accordion>
