DevSpace stores durable settings in `~/.devspace/config.jsonc`. It accepts
comments and trailing commas, is validated before the server starts, and
rejects unknown keys so typos cannot silently change behavior. Editor
completion comes from the versioned
[JSON Schema](https://raw.githubusercontent.com/Waishnav/devspace/main/schema/v1/devspace.schema.json).

The Owner password lives separately in `~/.devspace/auth.json`.

DevSpace reads configuration when `devspace serve` starts. After editing
`config.jsonc` or running `devspace config set`, restart the server to apply
changes, including allowed roots. Changes on disk do not hot-reload.

## Complete example

```jsonc ~/.devspace/config.jsonc lineNumbers
{
  "$schema": "https://raw.githubusercontent.com/Waishnav/devspace/main/schema/v1/devspace.schema.json",
  "configVersion": 1,

  "server": {
    "host": "127.0.0.1",
    "port": 7676,
    // Public origin only; do not append /mcp.
    "publicBaseUrl": "https://devspace.example.com",
    "allowedHosts": [],
    "trustProxy": false,
  },
  "workspaces": {
    "allowedRoots": ["~/personal", "~/work"],
    "worktreeRoot": "~/.devspace/worktrees",
  },
  "storage": { "stateDir": "~/.local/share/devspace" },
  // Optional: "codex" or "claude" gives every host that surface.
  // "tools": { "mode": "claude" },
  "ui": { "enabled": true },
  "activity": { "enabled": true, "maxTurns": 200 },
  "artifacts": { "enabled": false, "maxFileBytes": 104857600 },
  "skills": { "enabled": true, "paths": [], "agentDir": "~/.codex" },
  "subagents": { "enabled": false, "instructions": "on-demand", "providers": [] },
  "logging": {
    "level": "info",
    "format": "json",
    "requests": true,
    "assets": false,
    "toolCalls": true,
    "shellCommands": false,
  },
  "oauth": {
    "accessTokenTtlSeconds": 3600,
    "refreshTokenTtlSeconds": 2592000,
    "refreshTokenGraceSeconds": 0,
    "scopes": ["devspace"],
    "allowedResourceUrls": [],
    "allowedRedirectHosts": ["chatgpt.com", "claude.ai", "claude.com", "localhost", "127.0.0.1"],
  },
}
```

Omitted keys use the defaults shown.

## Server

`publicBaseUrl` is the tunnel origin MCP clients use for OAuth discovery.
Allowed Host headers derive from it, so requests through any other hostname
get `403 Invalid Host`; `["*"]` in `allowedHosts` is for local debugging only.

`trustProxy` controls which client IP DevSpace logs and rate-limits OAuth by.
`false` ignores forwarding headers. `"loopback"` trusts `X-Forwarded-For` only
from a proxy on the same machine, such as `cloudflared` or Tailscale Funnel —
the recommended value for tunnels. `true` trusts every hop, so any client can
choose its own IP.

## Workspaces

`allowedRoots` bounds where `open_workspace` may open. An empty list uses the
current working directory. `worktreeRoot` is where managed worktrees live.

## Tools and UI

DevSpace picks the tool surface for each host. `tools.mode` (`codex` or
`claude`) is an optional override that gives every host that surface — see
[Tool surfaces](/connect/tool-surfaces). `ui.enabled: false` removes widget
metadata but keeps `show_changes`.

## Activity

DevSpace records each workspace tool call, with its arguments and result, in
the local state database, grouped into turns that close at each
`show_changes`. Browse them at `/web` on your public origin after signing in
with the Owner password. Strings are truncated and common secret patterns are
redacted, but file contents and command output are kept as the tools returned
them.

`activity.maxTurns` caps the closed turns kept per workspace; older turns and
their calls are deleted. `activity.enabled: false` stops new recording without
deleting existing history.

## Skills

DevSpace discovers skills from `~/.agents/skills`, project `.agents/skills`,
`~/.devspace/skills`, `skills.agentDir/skills` (default `~/.codex/skills`), and
`skills.paths`. Relative custom paths resolve from the active workspace; add
legacy paths such as `.pi/skills` there when needed. Set `skills.enabled` to
`false` to hide skills from workspace output. See [Workspaces](/concepts/workspaces#skills).

## Subagents

`subagents.providers` lists explicit provider objects; omitted providers are
disabled. See [Providers](/orchestration/providers). Without a `subagents`
section, the `devspace agents` CLI can use every built-in provider whose CLI is
installed, while `serve` keeps subagents off for MCP hosts.

| `instructions` | Behavior |
| --- | --- |
| `on-demand` | Default. `open_workspace` advertises the `subagents` skill; the model reads it when delegation helps. |
| `preload` | The workflow is included in the initial `open_workspace` instructions. |

Neither mode tells the model to prefer subagents for routine work.

## OAuth

### Resource aliases

`allowedResourceUrls` accepts exact alternate MCP resource URLs for clients
connecting through an alias. The normal `server.publicBaseUrl` `/mcp` resource
is always allowed automatically. Supply a complete resource URL, such as
`https://alias.example.com/mcp`, rather than a hostname or origin. Aliases do
not change discovery URLs or proxy routing.

HTTPS is required, except HTTP on `localhost`, `127.0.0.1`, or `[::1]`, with
optional ports. Restart after changing the list. After restarting, refresh
tokens for removed aliases can no longer mint tokens.

The default `allowedRedirectHosts` covers ChatGPT and Claude; add hosts for
other MCP clients. An explicit list replaces the default, so keep `claude.ai`
in it to connect Claude.

### Refresh-token retries

`refreshTokenGraceSeconds` accepts integers from `0` to `600`. The default,
`0`, consumes a refresh token immediately. A positive value lets a trusted host
retry with the token it just rotated after a lost response or concurrent refresh.

On first use, the old token's expiry becomes the earlier of its original expiry
and first-use time plus the grace window. Retries never extend that deadline.
New refresh tokens keep `refreshTokenTtlSeconds`, and the old token's shortened
deadline persists across server restarts.

:::caution
Anyone holding the rotated token can reuse it during the grace window. Leave
this disabled unless you need it. Client, scope, resource, and revocation
checks still apply.
:::

## Environment

Only two persistent environment variables remain:

| Variable | Purpose |
| --- | --- |
| `DEVSPACE_CONFIG_DIR` | Location of `config.jsonc`, `auth.json`, skills, and profiles. |
| `DEVSPACE_OAUTH_OWNER_TOKEN` | Optional override for the stored Owner password. |

Two switches enable experimental features: `DEVSPACE_EXPERIMENTAL_CODE_MODE=1`
([code mode](/connect/code-mode) for MCP hosts) and `DEVSPACE_EXPERIMENTAL_WORKFLOWS=1`
([dynamic workflows](/orchestration/dynamic-workflows)).

Provider command overrides such as `CODEX_COMMAND`, `CODEX_HOME`, and
`CLAUDE_COMMAND` are still honored; provider config wins when both are set.

## v1.1 environment migration

Durable environment settings were removed in v1.1. Move existing deployment
values to these JSONC keys:

| Removed setting | JSONC key |
| --- | --- |
| `HOST`, `PORT` | `server.host`, `server.port` |
| `DEVSPACE_PUBLIC_BASE_URL` | `server.publicBaseUrl` |
| `DEVSPACE_ALLOWED_HOSTS` | `server.allowedHosts` |
| `DEVSPACE_TRUST_PROXY` | `server.trustProxy` |
| `DEVSPACE_ALLOWED_ROOTS` | `workspaces.allowedRoots` |
| `DEVSPACE_WORKTREE_ROOT` | `workspaces.worktreeRoot` |
| `DEVSPACE_STATE_DIR` | `storage.stateDir` |
| `DEVSPACE_TOOL_MODE`, `DEVSPACE_MINIMAL_TOOLS` | The tool surface is picked per MCP host; `tools.mode` is the optional override. |
| `DEVSPACE_WIDGETS` | `ui.enabled` |
| `DEVSPACE_ARTIFACTS` | `artifacts.enabled` |
| `DEVSPACE_ARTIFACT_MAX_FILE_BYTES` | `artifacts.maxFileBytes` |
| `DEVSPACE_SKILLS` | `skills.enabled` |
| `DEVSPACE_SKILL_PATHS` | `skills.paths` |
| `DEVSPACE_AGENT_DIR` | `skills.agentDir` |
| `DEVSPACE_SUBAGENTS` | `subagents.enabled` |
| `DEVSPACE_LOG_LEVEL` | `logging.level` |
| `DEVSPACE_LOG_FORMAT` | `logging.format` |
| `DEVSPACE_LOG_REQUESTS` | `logging.requests` |
| `DEVSPACE_LOG_ASSETS` | `logging.assets` |
| `DEVSPACE_LOG_TOOL_CALLS` | `logging.toolCalls` |
| `DEVSPACE_LOG_SHELL_COMMANDS` | `logging.shellCommands` |
| `DEVSPACE_OAUTH_ACCESS_TOKEN_TTL_SECONDS` | `oauth.accessTokenTtlSeconds` |
| `DEVSPACE_OAUTH_REFRESH_TOKEN_TTL_SECONDS` | `oauth.refreshTokenTtlSeconds` |
| `DEVSPACE_OAUTH_SCOPES` | `oauth.scopes` |
| `DEVSPACE_OAUTH_ALLOWED_REDIRECT_HOSTS` | `oauth.allowedRedirectHosts` |

These variables are not read or auto-imported. Environment is process state,
so DevSpace has no reliable file to migrate on your behalf.

## v1.0 file migration

On the first v1.1 load, DevSpace migrates only when `config.jsonc` is absent and
`config.json` exists:

1. Validate the old JSON document.
2. Translate its known fields into the versioned JSONC structure.
3. Write and validate a temporary `config.jsonc`.
4. Publish it atomically.
5. Rename the old file to `config.json.v1.0.bak`.

An existing JSONC file always wins. Invalid JSONC never falls back to the old
file, and unsupported legacy keys stop migration with an actionable error.

| v1.0 JSON field | v1.1 JSONC key |
| --- | --- |
| `host`, `port` | `server.host`, `server.port` |
| `publicBaseUrl`, `allowedHosts` | `server.publicBaseUrl`, `server.allowedHosts` |
| `allowedRoots`, `worktreeRoot` | `workspaces.allowedRoots`, `workspaces.worktreeRoot` |
| `stateDir` | `storage.stateDir` |
| `artifactsEnabled`, `artifactMaxFileBytes` | `artifacts.enabled`, `artifacts.maxFileBytes` |
| `agentDir` | `skills.agentDir` |
| `subagents` | `subagents` |
| `ui.enabled` | unchanged nested key |
| `tool_mode` | `tools.mode` |

`auth.json` is unchanged.
