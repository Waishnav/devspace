A coding harness does not need MCP to use DevSpace. It already has a shell.
Install the skill and it learns to call `devspace agents` directly — no MCP
server, OAuth, or tunnel. An on-demand local daemon owns execution.
Without a `subagents` section in your config, DevSpace detects the built-in
providers and uses each provider's default model. Claude and Pi ship inside
the package, so they need no separate CLI installation.

```bash
npm install -g @waishnav/devspace
devspace agents skill --install claude-code             # ~/.claude/skills/devspace-agents/SKILL.md
devspace agents skill --install claude-code --project   # .claude/skills/devspace-agents/SKILL.md
```

| Harness | Global location | `--project` location |
| --- | --- | --- |
| `claude-code` | `~/.claude/skills/devspace-agents/SKILL.md` | `.claude/skills/devspace-agents/SKILL.md` |
| `codex` | `~/.codex/skills/devspace-agents/SKILL.md` | `.agents/skills/devspace-agents/SKILL.md` |
| `opencode` | `~/.config/opencode/skills/devspace-agents/SKILL.md` | `.opencode/skills/devspace-agents/SKILL.md` |
| `cursor` | — | `.cursor/rules/devspace-agents.mdc` |
| `agents` | `~/.agents/skills/devspace-agents/SKILL.md` | `.agents/skills/devspace-agents/SKILL.md` |

For Codex, the global location is `$CODEX_HOME/skills/devspace-agents/SKILL.md`
when `CODEX_HOME` is set. The `agents` target installs into the shared Agent
Skills directory, which Codex and OpenCode also read. `--project` resolves from
the current Git root, or the current directory outside a repository.

The skill text ships with the package, so reinstall it after upgrading. Chat
apps connected over MCP don't need it; DevSpace manages their skill itself.

## Check availability

```bash
devspace agents targets
```

DevSpace reports usable providers and profiles, plus reasons for unavailable
providers:

```xml
<provider name="claude"/>
<unavailable name="cursor">cursor-agent executable not found; install it or set CURSOR_COMMAND</unavailable>
```

Availability checks executable or package discovery; it does not verify
sign-in. Use the provider's normal login flow before delegating. For an
external CLI, install it on `PATH` or set its `*_COMMAND` override, such as
`CURSOR_COMMAND`.

Any explicit `subagents` section replaces auto-detection. With
`subagents.enabled: false`, `targets` prints a `<disabled>…</disabled>` fragment.
Remove the section to restore detection, or configure the providers you want.

## Scope

Run agent commands from the project the subagent should use. DevSpace
discovers the current Git repository, or the current directory outside one.
Lists, lookups, and continuations stay inside that scope. Commands require the
complete logical agent ID returned by DevSpace; provider session IDs and ID
prefixes are not accepted.

## Example: Claude Code calls Codex

Inside Claude Code, a request like _"get a second opinion from Codex on this
migration, read only"_ becomes:

```bash
devspace agents run codex --effort high --write-mode read_only --wait \
  "Review db/migrations/0042_*.sql for data-loss risks. The table has 40M rows. Report findings with file:line."
```

`--wait` blocks until the turn ends and exits `0` completed, `2` failed, `3`
stopped, or `4` timed out; `1` means the command itself failed. A timeout or
Ctrl-C leaves the agent running. In scripts, always pass `--timeout`, then
`wait` again or `stop` the agent. The reverse works the same way: Codex can hand
implementation to Claude, OpenCode can ask Pi for a cheap exploration pass, and
any of them can fan out to several at once:

```bash
devspace agents wait agt_a agt_b agt_c --timeout 120
```

A multi-agent wait returns once all current turns end or the timeout passes. It
prints one observation per agent (a JSON array with `--json`), with duplicate
IDs once in first-seen order. Only the exit code is aggregated: if outcomes
differ, failed (`2`) wins over stopped (`3`), which wins over timeout (`4`).

## Parallel writers

Two agents editing the same checkout trample each other. `--worktree` gives an
agent its own Git worktree on branch `devspace/<agent id>`, created from the
committed `HEAD`; continuing the agent reuses it.

```bash
devspace agents run claude --worktree "Implement the retry policy in src/http.ts"
devspace agents run codex --worktree "Add the missing tests for src/queue.ts"
```

Merge the branches when you're ready. Worktrees live under
`workspaces.worktreeRoot` (default `~/.devspace/worktrees`) and are kept until
you remove them; `devspace worktrees prune` ignores CLI agent worktrees. See
[Subagents](/orchestration/subagents#worktrees) for review, merge, cleanup, and
recovery commands.

## From a bot or scheduled job

State and execution are per machine. Install the package where the code,
provider runtimes, and credentials live, then run it directly, over SSH, or
from cron. The local CLI does not connect to agents on another machine.
`--request-id` makes a retry return the same agent instead of starting a
second one:

```bash
ssh builder 'cd ~/src/app && devspace agents run claude \
  --request-id "nightly-$(date +%F)" --write-mode read_only \
  --wait --timeout 900 --json "Review yesterday'"'"'s commits for security issues"'
echo $?   # 0 done, 2 failed, 3 stopped, 4 still running
```

On exit code `4`, call `devspace agents wait <id> --timeout 900 --json` with
the id from the output. Provider credentials come from the user the command
runs as, so a non-interactive session needs the same logins and environment as
an interactive one. See [CLI](/reference/cli#safe-retries) for the request-ID
format and the arguments that must match on a retry.

## Write authority

| Mode | Meaning |
| --- | --- |
| `read_only` | Read and search without modifying files. |
| `allowed` (default) | Edit files in the project, sandboxed where the provider supports it. |
| `full_access` | No sandbox; use only for work you would run yourself unattended. |

Enforcement varies by provider. Generic ACP providers support only
`--write-mode full_access`. A continuation can lower write authority but cannot
raise it; an increase fails with `AGENT_CONFLICT`. Worktrees isolate files,
not local-user authority: a `full_access` agent can reach other checkouts by
absolute path.
