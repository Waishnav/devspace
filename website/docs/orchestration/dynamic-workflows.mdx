:::caution
Workflows are experimental in v1.1 and hidden by default. Set
`DEVSPACE_EXPERIMENTAL_WORKFLOWS=1` for both the CLI and daemon to enable the
`workflow` commands and managed workflows skill. If a daemon is already
running, stop it first:

```bash
devspace agents daemon stop
export DEVSPACE_EXPERIMENTAL_WORKFLOWS=1
```

The next workflow command starts the daemon with the flag. There is no
config-file switch or MCP workflow tool. The script API may change.
:::

A subagent is one delegation. A **workflow** is the loop around many of them,
written down: review a diff from three angles and synthesize; run the same
staged pipeline over forty files; try two implementations in isolated worktrees
and compare. The orchestrating model can write the script, launch it, and wait
on it — without holding the entire run in one tool call or its own context.

## A workflow script

Named workflows live at `.devspace/workflows/<name>.js`. An optional first
statement exports literal metadata; the rest composes primitives and returns a
JSON-compatible result. Scripts run in an isolated JavaScript sandbox with no
filesystem or network access — only the primitives below.

```js .devspace/workflows/review-auth.js lineNumbers
export const meta = {
  name: "review-auth",
  description: "Review auth changes from two perspectives",
  concurrency: 2,
};

const reviews = await phase("Review", (agent) => parallel(
  [
    { target: "reviewer", focus: "correctness" },
    { target: "claude", focus: "security" },
  ],
  ({ target, focus }) => agent(`Review the auth diff for ${focus}.`, { target, label: focus }),
));

const summary = await phase("Synthesize", (agent) => agent(
  `Synthesize these reviews: ${JSON.stringify(reviews)}`,
  { target: "codex", label: "summary" },
));

return { reviews, summary };
```

## Primitives

| Primitive | What it does |
| --- | --- |
| `agent(prompt, options)` | One bounded delegation; resolves to the agent's response. `options.target` (a provider or profile) is required. Also: `model`, `effort`, `label`, `schema`, `writeMode`, `isolation: "worktree"`, `workspace`. |
| `phase(name, (agent) => …)` | Groups calls under a named phase; the callback's `agent` tags each call with it. |
| `parallel(items, worker, concurrency?)` | Runs `worker(item, index)` over items, at most `meta.concurrency` (default 4) at a time. Resolves to `{ status: "completed", value }` or `{ status: "failed", error }` per item, in order. |
| `pipeline(items, ...stages)` | Runs each item through dependent stages — `stage(value, item, index)` — with the same per-item outcomes as `parallel`. |
| `workflow(name, args?)` | Compose another named workflow. |
| `log(...values)` | Record progress in the run's event log. |
| `args` | The run's arguments, passed as JSON with `--args`. |

### Structured results

Ask for typed JSON when a later step consumes the output. DevSpace validates
the response against the schema and asks the agent once to correct invalid
JSON. The single correction turn is read-only, uses the same agent session,
and counts toward the run's 128-turn budget.

Schemas use strict draft-07 structural constraints, with limits of 16 KiB,
512 nodes, and 16 levels. `$ref`, `$dynamicRef`, `$recursiveRef`, `$async`,
`pattern`, `patternProperties`, and `format` are rejected.

```js
const review = await agent("Return the discovered bugs.", {
  target: "codex",
  schema: {
    type: "object",
    properties: { bugs: { type: "array", items: { type: "string" } } },
    required: ["bugs"],
  },
});
```

### Writers

Runs are read-only unless started with `--write-mode allowed`. Within a writing
run, `isolation: "worktree"` gives a call its own Git worktree, so parallel
agents that edit overlapping files never collide:

```js
const [lru, ttl] = await parallel(
  [{ target: "claude", kind: "an LRU" }, { target: "codex", kind: "a TTL map" }],
  ({ target, kind }) => agent(`Implement the cache with ${kind}.`, {
    target, writeMode: "allowed", isolation: "worktree",
  }),
);
```

Profiles resolve in each call's execution workspace. Isolated worktrees start
from committed `HEAD`, without uncommitted source changes, so use global
profiles or commit project profiles before launching isolated calls.

These are managed workspaces retained for inspection. Normal stale-worktree
cleanup preserves recovery snapshots for commits and dirty tracked changes,
and skips worktrees with untracked files. CLI agent worktrees created by
`agents run --worktree` have a separate lifecycle and are ignored by prune.

## Run and inspect

```bash
devspace workflow run --name review-auth
devspace workflow run --file ./scratch.js --args '{"pr":482}'
devspace workflow wait <run-id> --timeout 60
devspace workflow status <run-id>
devspace workflow calls <run-id>
devspace workflow call <run-id> <call-index>
devspace workflow events <run-id> --after <sequence>
devspace workflow cancel <run-id>
devspace workflow ls
```

`run` returns a receipt with the run ID, then the CLI exits. Active workflows
keep the daemon alive. Records, calls, and provider continuation state survive
CLI exit and daemon restarts. After a restart, unfinished runs become
`interrupted`; DevSpace does not automatically dispatch calls.

Choose exactly one of `--file`, `--name`, or `--resume`. Pass JSON arguments
with `--args <json>` or `--args-file <file>`, never both. Named workflows,
arguments, and run lookups are scoped to the current checkout or worktree;
an ID from another scope is rejected.

| Inspection | Behavior |
| --- | --- |
| `wait` | Wait 0–60 seconds, default 60; return the latest stored state on timeout. |
| `calls` | Compact summaries without prompts, results, or fingerprints. |
| `call` | Full stored record for one zero-based call index. |
| `events --after <sequence>` | Up to 100 persisted entries after the sequence. |

From an agent harness, `wait` in bounded steps instead of polling `status`.
Add `--json` for scripts.

## Limits

| Boundary | Limit |
| --- | --- |
| `meta.concurrency` | 1–16, default 4. |
| Active workflows per daemon | 8. |
| Aggregate workflow agent turns per daemon | 8 at once. |
| Script runners per daemon | 16, including nested scripts. |
| Agent turns per run | 128, including schema corrections. |
| Nested invocations per run | 8; maximum nesting depth 1. Nested calls share the parent's budgets and cancellation. |
| QuickJS heap / stack | 32 MiB / 512 KiB. |
| Script wall clock | 15 minutes. |
| Script source / arguments | 64 KiB / 128 KiB. |
| Workflow or agent result | 256 KiB. |
| Guest `log` / `phase` events | 64 KiB combined per run; bounded internal events are additional. |

These are execution boundaries, not config tuning controls.

## Resume

Failed, cancelled, and interrupted runs are terminal. Resume one to reuse its
completed calls:

```bash
devspace workflow run --resume <run-id>
```

A resumed run uses the original script, arguments, and authority. It reuses
only a matching prefix of completed read-only calls, then executes live from
the first nonmatching or unfinished call. **Any** recorded call with write
authority, `isolation`, or a named `workspace` disables replay for the run;
inspect its calls and preserved worktrees, then start a new run.

DevSpace fingerprints `HEAD`, the staged diff, and files selected by
`git ls-files --cached --others --exclude-standard`. Ignored untracked files
are excluded, so changes to ignored build output do not block resume. A changed
context, more than 20,000 entries or 64 MiB of files, a symlink, a special or
unreadable file, or another fingerprint failure produces
`RECOVERY_CONTEXT_CHANGED`.

:::warning
Scripts must be replayable. Do not use `Date.now()`, `Math.random()`, or
argument-less `new Date()`. Pass changing values through `args`.
:::
