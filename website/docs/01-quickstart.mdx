DevSpace needs Git and a Bash-compatible shell (Git Bash or WSL on Windows).
The installer brings its own Node when yours is missing or outside
`>=22.19 <27`.

<Steps>
  <Step title="Install and run setup">
    <Tabs>
      <Tab title="macOS / Linux / WSL">
        ```bash
        curl -fsSL https://devspace.run/install | sh
        ```
      </Tab>
      <Tab title="Windows">
        ```powershell
        powershell -c "irm https://devspace.run/install.ps1 | iex"
        ```
      </Tab>
    </Tabs>

    The installer uses a compatible Node on your `PATH` or downloads a
    checksum-verified Node 24 LTS for DevSpace alone, installs DevSpace without
    `sudo`, puts `devspace` on your `PATH`, and starts `devspace init`. Rerun it
    to update.

    Already manage Node yourself? `npm install -g @waishnav/devspace` and
    `devspace init` work too.

  </Step>
  <Step title="Choose where you will use it">
    Setup asks one question at a time. First: **ChatGPT**, **Coding Agents**,
    or both. This is where _you_ invoke DevSpace from — it skips the setup that
    does not apply.
  </Step>
  <Step title="Choose your subagents">
    DevSpace detects the harnesses installed on your machine — Codex, Claude
    Code, OpenCode, Pi, Cursor, Copilot, Grok — and asks which ones it may run
    as subagents. The choice is stored under `subagents` in
    `~/.devspace/config.jsonc`.
  </Step>
  <Step title="Finish the path you picked">
    <Tabs>
      <Tab title="Coding Agents">
        Setup prints a Skills CLI command. Run it and pick which installed
        harnesses receive the skill:

        ```bash
        npx skills add Waishnav/devspace --skill subagents --global
        ```

        No server is needed. The skill teaches the harness the
        `devspace agents` commands.
      </Tab>
      <Tab title="ChatGPT">
        Setup asks for the project folders ChatGPT may open and the public
        HTTPS origin of your tunnel (without `/mcp`). Then start the server:

        ```bash
        devspace serve
        ```

        Add `https://your-tunnel.example.com/mcp` as a connector and approve it
        with the Owner password printed by setup. See
        [Connect an MCP host](/connect/mcp-hosts).
      </Tab>
    </Tabs>

  </Step>
</Steps>

## Let your agent set itself up

A coding agent can do all of the above for itself. Paste this into Codex,
Claude Code, or any agent with a shell — every step runs without prompts:

```text
Set up DevSpace (https://devspace.run) on this computer so you can delegate
coding work to my other coding agents.

1. Install or update it:
   curl -fsSL https://devspace.run/install | DEVSPACE_NO_INIT=1 sh
2. Configure it: devspace init --yes
3. Install the subagents skill for yourself:
   devspace agents skill --install <claude-code|codex|opencode|agents>
   (Cursor: devspace agents skill --install cursor --project, from the project root)
4. Check it works: devspace agents targets
```

The **Copy prompt** button on [devspace.run](https://devspace.run) copies a
version that also covers Windows. To answer setup questions with flags, see
[init options](/reference/cli#init-options).

## Your first delegation

From a project directory, ask your harness to delegate — or try the commands
yourself.

```bash
devspace agents targets
```

```xml
<provider name="codex" model="gpt-5.4" effort="high"/>
<provider name="claude" model="sonnet"/>
```

Pick any listed target — a provider, or a [profile](/orchestration/profiles)
you've created:

```bash
devspace agents run codex --write-mode read_only "Review the uncommitted diff for correctness and missing tests. Cite files."
# <agent id="agt_7Kq2" status="running"/>

devspace agents wait agt_7Kq2
# <agent id="agt_7Kq2" status="completed">findings: …</agent>
```

The harness that ran these commands is now an orchestrator: it chose a target,
wrote a self-contained brief, and blocked on the result without holding the
work in its own context.

## Check your setup

```bash
devspace doctor
```

`doctor` reports the resolved config, Node version, platform, Git, Bash,
public URL, allowed hosts, and SQLite status.
